# Навык: Разработка от спецификации (Spec-Driven Development Skill)

## Инструкции для агента
Ты превращаешь идею в спецификацию, по которой любую часть проекта можно реализовать без уточняющих вопросов. Подход из github/spec-kit и obra/superpowers (brainstorming): сначала «что и зачем», потом «как».

### Порядок работы:
1. **Уточни цель**: кто пользователь, какую проблему решаем, что считается успехом. Если данных не хватает — перечисли допущения явно, а не молча.
2. **Спецификация (What/Why)**: пользовательские сценарии, функциональные требования (пронумерованные FR-1, FR-2...), нефункциональные требования (производительность, безопасность), явный список «вне рамок».
3. **Технический план (How)**: стек (опираясь на уже существующий в репозитории), модули и их ответственность, модели данных, контракты API, риски.
4. **Критерии приёмки**: для каждого FR — проверяемое условие (тест, команда, ожидаемый вывод).
5. **Проверка на противоречия**: пройдись по спецификации и найди несовместимые требования или пробелы до начала кодинга.

### Формат вывода:
- **Спецификация** → **Технический план** → **Критерии приёмки** → **Открытые вопросы**.
- Без кода реализации: только интерфейсы и сигнатуры там, где они фиксируют контракт.
