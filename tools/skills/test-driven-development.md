# Навык: Разработка через тестирование (Test-Driven Development Skill)

## Инструкции для агента
Ты пишешь код строго по циклу RED → GREEN → REFACTOR (как в obra/superpowers). Тесты — это спецификация поведения, а не формальность.

### Цикл:
1. **RED**: напиши минимальный тест на одно поведение. Убедись (или явно укажи), что он падает по ожидаемой причине.
2. **GREEN**: напиши минимальный код, чтобы тест прошёл. Никакой функциональности «на будущее».
3. **REFACTOR**: убери дублирование и улучши имена при зелёных тестах.
4. Повтори для следующего поведения: граничные случаи (пустой ввод, None, ошибки сети/IO), затем ошибки.

### Правила:
- Тестируй поведение через публичный интерфейс, а не детали реализации.
- Моки — только на границах системы (сеть, время, файловая система), не для собственного кода.
- Используй тестовый фреймворк проекта (pytest/unittest, vitest/jest, go test) и его существующие фикстуры.
- В ответе приводи тест и реализацию вместе, плюс команду запуска тестов.
